## Selected features and excluded terms

LVGL uses the C runtime allocator/string/formatting functions, its own software
renderer and an original static bitmap font. All bundled fonts are disabled,
including both separately controlled Montserrat 14 and Montserrat 14 aligned.
Montserrat/FontAwesome/CJK assets, examples/demos, commercial tooling, compressed
fonts, external font/image loaders, optional codecs, FreeType, TinyTTF, ThorVG,
FFmpeg and network/filesystem image inputs are not selected. No OFL or commercial
asset is adopted. The inspected complete upstream archive is not a public package
input; selected build artifacts and notices must be checked before distribution.

SDL selects static core, X11/dummy video, software rendering and pthread/POSIX
services. Audio, joystick, haptic, HIDAPI, sensor, DBus/IBus, Wayland, OpenGL/GLES,
Vulkan, KMSDRM, libudev and optional X11 extensions are disabled. Raw Linux evdev
and console-keyboard features are explicitly disabled; no privileged input-device
mount is needed. Selected target sources exclude unused `src/libm` fallback
objects (SunPro terms). System libc math and `HAVE_STRTOK_R` are required, so the
CC0 fallback branch in SDL_strtokr is not selected. Do not silently fall back to
those excluded components on another platform. Retain the MIT/BSD notices for
the selected conversion/EDID/yuv code even where that feature is not called by UI.

The selected profile has actually built and opened an X11 software window in
WSLg. A font probe rendered through LVGL without bundled fonts. These feasibility
checks do not replace application integration, usability or security verification.

## Platform dependencies and failure impact

GCC/CMake/CPython, glibc/libstdc++, pthread/dl/math and X11/Xext platform libraries
are tracked separately from application libraries under the dependency policy.
M1–M5 build/runtime pins remain documented; GUI platform package versions and
inventories will accompany the actual native/container builds. Native inspection
used existing X11 and a locally extracted authenticated Ubuntu libxext-dev
`2:1.3.4-1build2` package (SHA-256
`b5bdb6724f228cb8eee8cf39cbbe1289dd3f8f06dd022748312df7844c94dcf2`), without a global
installation. Existing TLS/certificate configuration is retained.

The UI is an observation/request client, not a protective controller. Framework
failure may hide/misstate information or interrupt operator requests; protection
and plant arbitration continue separately. Bounded worker communication, stale
indicators, role mounts, exact response parsing and no automatic critical-command
retry mitigate specific software failure paths. Shared host/display-server and
protocol failures remain common causes, not hardware independence evidence.

On the selection date, the maintainer [LVGL advisory page](https://github.com/lvgl/lvgl/security/advisories)
and [SDL advisory page](https://github.com/libsdl-org/SDL/security/advisories) showed
no published advisories. This is limited coverage, not absence of vulnerabilities;
broader available analysis/inventory and findings are required in M8. Untrusted
external fonts/images are not accepted by this UI. Redistribution must include
the selected notices and separately satisfy shipped platform-package obligations.

The actual Docker GUI build selects Debian snapshot `20260824T000000Z`:
`libx11-dev=2:1.8.12-1`, `libxext-dev=2:1.3.4-1+b3`; runtime pins
`libx11-6=2:1.8.12-1`, `libxext6=2:1.3.4-1+b3`. Snapshot-resolved transitive
platform packages include libxcb, libXau and libXdmcp; exact installed inventories
remain `/opt/bin/build-packages.txt` and `/opt/bin/runtime-packages.txt` in each
image. These are platform packages, not blanket permissive-application claims.
Two symlinks belonging to the unused SDL Android Ant project are explicitly
excluded from extraction and named in the lock. Other unexpected links fail.
Verified archives are rechecked and the complete extracted regular-file tree is
compared with archive digests at configure time; a stamp alone is insufficient.
