# M1 dependency selection

M1 introduces no third-party application library, pip package, copied numerical
code, GUI asset or crypto implementation. Project C++17/Python code is MIT.
Linux/POSIX sockets, the C++ runtime and CPython are platform dependencies.
They remain shared failure sources; a license preference is not a security review.

| Component / purpose | Selected version | License / provenance |
| --- | --- | --- |
| Official Python container / runtime and build base | CPython 3.12.14, Debian 13 trixie, `python@sha256:7a8b475003c4fe15a2cd4e55e5cfc2f3560bdc9333d624f24cdd6d4340fd7a17`, linux/amd64 | PSF-2.0 plus Python's historical/bundled notices; image digest verified from local Docker repository metadata. [Python license](https://docs.python.org/3.12/license.html). |

| CMake / configuration | Debian 3.31.6-2 | BSD-3-Clause; [official license](https://cmake.org/licensing/). |

| Docker / Compose / deployment | Host 29.3.1 / v5.1.1 | External host tools; not bundled in the application image. |

All build dependencies resolve from the fixed Debian snapshot
`https://snapshot.debian.org/archive/debian/20260824T000000Z` with authenticated
Debian package metadata. The snapshot is immutable; expiry checking alone is
turned off, signature checking remains on. No floating apt repository or image tag
is a build input. The final image retains base-image notices and contains build and
runtime `dpkg-query -W` inventories at `/opt/bin/*-packages.txt`.

The native environment inspected was GCC 13.3.0, CMake 3.28.3 and Python 3.12.3 on
Ubuntu/WSL2 x86_64. Native commands reproduce the model but the pinned container is
the selected M1 build environment. Run manifests record actual compiler/source and
binary hashes, configuration, interpreter and platform. Build repeatability is
checked separately from trajectory repeatability; no cross-toolchain binary
identity claim is made.

Build tools and Linux system/runtime packages are tracked separately under
`DEPENDENCY_POLICY.md`; no application-library exception is introduced. Python's
runtime is already required by the project architecture. Redistribution of complete
images needs retention of all supplier notices and applicable source/relinking
obligations; this source milestone does not approve an image distribution. A full
shipped-image SBOM, vulnerability triage and independent dependency review remain
open release prerequisites. No claim is made that pinning establishes absence of
known vulnerabilities. Changes to the digest, snapshot, features or licenses
require renewed inventory and impact review.
