Application versions/features/licenses remain those of M6/M7. The versioned
`dependency_inventory.json` binds their immutable archives, selected embedded
code/fonts, notices and build profile. `tools/dependency_report.py` validates
these bindings and produces deterministic CycloneDX 1.6 application/actual-image
SBOMs, actual binary hashes and separate native/container package inventories.

non-machine-readable labels are not invented SPDX conclusions. This is not full
image redistribution clearance. CI tools are assessed in `CI_NOTICES.md`.

in `build/m8-security-scan-second/`. Matching records require triage; not every

## Analysis coverage and limits

Cppcheck 2.13.0 examines project C/C++ warning/performance/portability paths.
An initial conservative role-index warning prompted explicit listener bounds and
an enumerated sensor-role branch; later output must identify the inspected hashes.
External GUI-header semantics, all upstream code and complete path coverage are
not established by that scan. Actual sanitizer/process/widget tests complement it.

OSV queries use exact application commits, actual Debian 13 **source** package
versions, interpreter Git tag and installed PyPI versions. They exhaust pagination,
retain errors as BLOCKED, and never substitute binary-package guesses for source
versions. Database matches do not establish reachability; no matches do not prove
coverage. Raw data and public factual summaries preserve upstream references.
Current findings and dispositions will accompany the final M8 evidence.

The updated visible runtime filesystem removes unused pip and ensurepip bootstrap
wheels: these services use only the standard library and never install packages
while running. This reduces executable attack surface; it does **not** erase bytes
or redistribution obligations in inherited immutable base layers. Installed-package
SBOMs describe the effective filesystem and separately identify the base digest;
they are not a forensic inventory of every deleted/lower-layer file. Preserve the
initial pip findings as removed-from-active-runtime, not as a patched upstream tool.

The selected-image scan completes 70 queries with zero blocked queries and 19
matching queries / 73 unique advisory IDs. `assurance/DEPENDENCY_FINDINGS.json`
keeps every match open with deployment constraints and next action. This is not
risk acceptance or a clean image assertion. Linked libc/libstdc++/compression and
optional X11 paths receive no blanket non-reachability claim. Other installed
platform commands are not invoked by fixed service commands, but remain inventoried.
The Debian tracker still identifies affected trixie zlib and libX11 packages; do not
mix unstable distribution packages merely to make a scan green. Upstream/distro
patch tracking and full redistribution/risk decisions remain open release work.
Primary examples: https://security-tracker.debian.org/tracker/CVE-2026-27171 and
https://security-tracker.debian.org/tracker/CVE-2026-88806. These limits apply to the
trusted local simulation profile; no broader secure deployment is claimed.
